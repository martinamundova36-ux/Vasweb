# Student House Bratislava — deployment status, 12 November 2026

This is an incremental repair of the existing Vasweb portal, not a second app. Complete production acceptance is NOT established.

## Implemented and checked

- Existing separate student/staff session stores and role gates retained. Chromium: 12 combinations of three roles, two entrypoints, desktop/mobile widths, including authenticated SK/EN/RU/UK switching. Auth SDK is synthetic in these UI tests.
- Room table: all existing rooms, every current occupant, search/filter/sort, room edits with optimistic concurrency, CSV export with spreadsheet formula escaping, validated insert-only CSV import. Real tenant-scoped Supabase data and existing RLS/audit triggers are used.
- Student House inventory: 61 existing database rooms; 3 clearly unconfirmed UI inventory positions to reach the requested 64. No invented room numbers or production rows inserted. Unconfirmed positions are not counted as available rooms. Other tenant data remains isolated by RLS.
- Room table includes contract/date/rent/payment allocation/document review/cleaning information. Charges and payment allocations exclude reversals; monthly balances now show allocated amounts and remaining charge balances.
- Atomic registration approval: staff review the contractual monthly rent, due day and EACH monthly charge (partial months editable). Membership/resident/tenancy/charges/status commit together. Capacity, overlap, identity, contract duplication, duplicate requests and schedule validation are enforced in PostgreSQL. No received payment is fabricated.
- New verified receipts are transactionally allocated to charges by earliest due date. Partial/split payments, duplicate references, reversals and overpayment credit are covered by isolated PostgreSQL tests. Historical receipts are not rewritten.
- Live public mobile Chromium check: student, registration and reception URLs each returned HTTP 200, build 20261112-atomic2, no JavaScript page errors, and no visible authenticated application before sign-in. This does not prove password login or inbox delivery.
- Existing direct invitations and private document download branch preserved against live manage v7. manage v8 deployed after 9 handler regression scenarios passed with synthetic transports.
- Profile read policy consolidated to own active profile + valid session. IMPORTANT: the previous policy expression alone did not establish a privacy leak; original migration defined the session policy as RESTRICTIVE. We did not prove foreign profile exposure before consolidation.
- Additive database migrations applied; no table, room, resident or contract deleted. New approval RPC executable only by service_role; verified anon/authenticated denied by database ACL metadata. Capacity decrease guard installed.
- Browser modules use versioned URLs; HTML exposes build marker 20261112-atomic2. GitHub Pages controls HTML cache TTL; no claim of forcibly clearing existing browser caches.

## Reproduce isolated tests

From repository root: `npm ci --prefix tests --ignore-scripts`, then `npm test --prefix tests`.
Install Chromium using the pinned Playwright dependency: `npx --prefix tests playwright install --with-deps chromium`; then `npm run browser --prefix tests`.
For a preinstalled browser set CHROMIUM_PATH. All fixtures are synthetic and execute locally. No service key or test password is required. Fixtures under tests/fixtures/base are historical schema snapshots for isolated test bootstrap, NOT production deployment migrations.
